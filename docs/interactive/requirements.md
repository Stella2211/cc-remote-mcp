# 対話セッションの要件

## 起動（`start_interactive`）

以下は macOS / Linux（tmux）の要件。Windows は末尾の節。

- パスは rc と同じ方針で検査する（`resolveDir`、ホームディレクトリは拒否）。
- 実行するのは `tmux -u -L cc-remote-mcp -f /dev/null new-session -d -s <id> -x 200 -y 50 -- <claude> --remote-control=<名前> --name <名前> [--permission-mode <モード>] [--worktree] -- "<プロンプト> "` と、同じ呼び出しの中の `set-option`（`remain-on-exit on`、`@cc_remote_mcp_name`）だけ。引数は配列で渡し、シェルを通さない。
- 起動場所（`resolveDir` の実体パス）は `-c` で渡さず、tmux をその場所で起動する（`PWD` も実体パスにする）。tmux は `-c` の値を書式として展開し（`#(…)` はシェルで実行、`#{…}` は置き換え）、末尾の `;` は区切りになるため。作成後に `#{session_path}` が実体パスと違えば、そのセッションを消して `spawn_failed` にする。
- tmux は「`;` で終わる引数」をコマンドの区切りとして読む。プロンプトの末尾には空白を1つ足し、名前は `;` で終わるものを拒否する（自動の名前は末尾の `;` を除く）。末尾の空白は、プロンプトがサブコマンド名（`install` など）と同じでも claude にサブコマンドとして読まれないためでもある。
- プロンプトの `--` より後ろは位置引数なので、`-` で始まってもフラグにならない。
- プロンプトは空白だけを拒否し、改行とタブ以外の制御文字を拒否し、UTF-8 で 12000 バイトまで（tmux の1コマンドは約16KBまで）。
- 名前は rc と同じ（64文字まで、`-` で始まらない、制御文字なし）に加えて `;` で終わらない。省くと「端末名-ディレクトリ名」。
- 権限モードは rc と同じ4つ。`default` は `manual` にして渡す。
- 同時実行数は rc と対話セッション（生きているもの）の合計で `MAX_SESSIONS` まで。同時に来た起動（rc との組み合わせも）でもすり抜けない。
- 起動後、URL が画面に出るか、終了するか、8秒たつまで0.5秒ごとに画面を見て、画面の末尾20行（1行300文字、ANSI を除く）をつけて返す。

## 入力（`send_input`）

- id は `cc_` で始まり、専用ソケットにあるセッションだけ。終了したセッションには送らない。
- `text` と `key` のどちらか一方。`text` は改行とタブ以外の制御文字を拒否し、20000文字まで。`\r\n` と `\r` は `\n` にそろえる。
- `text` は `load-buffer -b <使い捨ての名前> -`（標準入力）で渡し、`paste-buffer -p -d` で括弧付き貼り付けとして流す。`submit`（既定 true）なら0.3秒待って `Enter`。
- `key` は `Enter` / `Escape` / `Up` / `Down` だけ（`Shift+Tab` のモード切り替えと `Ctrl+C` は送らせない）。

## 一覧と停止

- `list_sessions` の応答に `interactive` を足す。古いクライアントは返さないので、Worker は無いものを空として扱う。
- 一覧は専用ソケットの `cc_` で始まるセッションだけ。終了して30分たったものは一覧のときに消す。終了したものだけ画面の末尾をつける。
- 停止（`stop_interactive`）は `C-c` を2回（0.3秒あけて）送り、10秒後に `kill-session`。終了済みならすぐ `kill-session`。
- クライアントが止まるとき、tmux の対話セッションは止めない（Windows は末尾の節）。ただし Linux の systemd は `KillMode=mixed` でサービスの cgroup ごと止めるので、tmux も一緒に止まる。

## ログと通知

- クライアントのログに、起動（端末名・id・パス・名前・プロンプトの文字数）、入力（id・文字数か押したキー・submit）、停止を JSON で残す。
- ログに残すのはプロンプトと入力の文字数だけで、中身は残さない。
- Worker のログは操作名・端末名・結果の種別・所要時間だけ。Discord 通知は起動と停止（端末名・場所・状態）だけで、プロンプトと入力は送らない。

## Windows（疑似端末）

- MCP の引数・返り値・ID（`cc_`）・上限・待ち時間・ログは macOS / Linux と同じ。違うのは端末の中の作りだけ。
- Bun 1.3.14 未満なら対話セッションを使えない（`bun upgrade` を促す `spawn_failed`）。rc は使える。
- 起動は `Bun.spawn([<claude.exe>, --remote-control=<名前>, --name, <名前>, [--permission-mode, <モード>], [--worktree], --, "<プロンプト> "], { cwd: <実体パス>, terminal: { cols: 200, rows: 50 } })` だけ。cmd・PowerShell を通さない。環境変数からクライアント自身の設定を除く。
- 出力は端末エミュレーター（`@xterm/headless`、200×50）に流し、その表示部分（折り返しはつなぐ）を画面とする。端末への問い合わせへの返事は claude に書き戻す。
- URL は画面に加えて、生の出力（末尾 4000 文字を持ち越し、出力の末尾で切れているものは次を待つ）からも拾う。
- `text` は改行を CR にして、claude が括弧付き貼り付け（`ESC[?2004h`）を有効にしていれば `ESC[200~`…`ESC[201~` で囲んで書く。`submit` なら0.3秒待って CR。
- キーは Enter=CR、Escape=ESC（単独で書く）、上下=`ESC[A` / `ESC[B`（カーソルキーのアプリケーションモードなら `ESCOA` / `ESCOB`）。停止の Ctrl+C は `0x03`。
- 終了コードはプロセスの終了から取る。遅れて届く出力を画面に入れるため、終了の0.3秒後に「終了」とする。終了したものは画面を残し、30分後の一覧で消す（tmux の `remain-on-exit` と同じ）。一覧が呼ばれなくても31分後に消す。
- 消すとき（停止の猶予の後・片付け）は、動いていれば先にプロセスツリーを `taskkill /T /F` で止め、終了を（最大3秒）待ってから疑似端末を閉じる（古い Windows は子が動いたまま閉じると close が戻らないことがある）。
- クライアントが SIGINT / SIGTERM を受けたら、動いている対話セッションに Ctrl+C を2回送り、2秒後に強制終了する。
