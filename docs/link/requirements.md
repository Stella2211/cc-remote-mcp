# 接続の要件

## プロトコル（`shared/protocol.ts`）

- Worker → クライアント：`{type:"request", id, action, params}`。
- クライアント → Worker：接続直後に `{type:"hello", protocol, clientVersion, platform}`、応答は `{type:"response", id, ok:true, result}` か `{..., ok:false, error:{code, message}}`。
- `clientVersion` は `^[0-9A-Za-z][0-9A-Za-z.+_-]{0,31}$`（半角英数字と `.+_-`、32文字まで）。外れた hello は他のスキーマ違反と同じく捨てる（版は更新されない）。`list_devices` では保存済みの値も `literal` を通して出す。
- 1通 256KB（UTF-8 のバイト数）まで。超えたもの・JSON でないもの・スキーマに合わないものは捨てる。
- ハートビートは文字列 `ping` / `pong`。

## DO（`DeviceHub`）

- 1端末1接続。新しい接続が来たら古い方をコード 4000 で閉じる。古い方が閉じても、新しい方が生きていれば切断扱いにしない。
- 応答は、リクエストを送ったその接続からのものだけを受け付ける（別の端末が答えを偽れない）。接続ごとの識別子（`connId`）を attachment に入れて比べる。休止から戻ると WebSocket のオブジェクトが作り直されるため、オブジェクトの同一性では比べない。
- `call` は20秒で `timeout`。接続が切れたら待っていたリクエストは `offline` で終える。
- `listDevices` と `call` のたびに `DEVICE_KEYS` を読み直し、外れた端末の接続と、接続したときとハッシュが変わった（トークンを入れ替えた）端末の接続を 4003 で閉じる。
- 端末ごとに OS・クライアントの版・接続 / 切断 / 最終応答の日時を SQLite に残す。

## クライアント

- 切れたら指数バックオフ（1秒から倍々、最大60秒、0.5〜1倍の揺らぎ）でつなぎ直す。1分つながっていたら回数を戻す。
- 25秒ごとに ping、10秒以内に pong がなければ張り直す（スリープ復帰や回線の切り替え）。接続が15秒たっても開かなければ張り直す。
- 4000（置き換え）で閉じられたら5分待つ。
- 接続に失敗したら、`error` のログに理由（`reason`）とコード（`code`、`ENOTFOUND` など）を残す。ヘッダー（トークン）は入れず、長い文字列は伏せる。
